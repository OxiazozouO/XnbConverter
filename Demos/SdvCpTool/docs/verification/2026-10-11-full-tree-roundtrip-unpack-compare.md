## 那 2188 张"像素不一样"的图：**预乘 alpha**，不是画错了

`PIL` 两两比（把 `P` 调色板图也统一转成 RGBA）：

```
共同 png 3301：像素相同 1480、尺寸不同 0、**像素真的不同 1821**
```

抽查 `Animals/BabyBlue Chicken.png`（源里 64×224）：**9679 个不同的像素，
全部**满足 `解回 = round(源 × alpha/255)` —— 一个不差。

**判定它不是损失**的决定性实验：拿**原版** `Content/Animals/BabyBlue Chicken.xnb`（64×112，没被模组改过）
走一遍 `解包 → 打包 → 再解包`：

```
7168 个像素**一模一样**（0 个不同）
```

⇒ 打包器/解包器这一对**在同一个表示上自洽**（原版资产往返完全幂等）；
而**模组给的 PNG 是直通 alpha**，打包时被**乘一次 alpha** ⇒ 解回来的 PNG 看着"变暗"，
但那正是 **XNB 里纹理的表示**（XNA 的 `Texture2D` 要的就是预乘）⇒ 游戏里显示**是对的**。
⚠ 别把这个当成数据丢失；要肉眼比就得先反预乘。

## 那 72 个 JSON 差异：逐类查过，都不影响玩法

| 类别 | 例 | 说明 |
|---|---|---|
| 缺省字段的**物化/省略** | `Data/Buildings` 里一大批 `ActionTiles: []`、`DrawShadow: true`… | 模型往返的必然产物；游戏按缺省值走，语义不变 |
| 值的**大小写归一** | `Crops.Seasons: ["spring"] → ["Spring"]`、`CanSocialize: true → "true"` | 游戏那边大小写无关；`CanSocialize` 在模型里本来就是**字符串（GSQ）** |
| **框架专属字段** | `BigCraftableData.CustomFields` | 模型里带了但工具没往返（消费者是模组的 C#，本场景里不存在）|
| **只读计算属性** | `BuildMaterial.Id` | 模型里是 `public string Id => ItemId;`（**只有 get**，`BuildingMaterial.cs:10`）⇒ 序列化本来就不写它 ⇒ **游戏自己的管线也一样**，不是丢 |
| 模组**自造字段** | `CharacterData.ExcludeFromIntroductionsQuest` | 游戏模型里**没有**这个字段（`sdv_gd` 里查过）⇒ 丢它是必然 |
| **非原版命名空间的资产** | `Data/AntiSocialNPCs`（源里 `{"Alesia": true}`）| 我们给它配的 `.config` 模板与它的类型不匹配 ⇒ 打包时按别的模型序列化，解回来是**另一批字段**。本场景里没人读它（读它的是那个 C# mod）⇒ 是**死重量**，不是玩法损失 |

## 一句话结论

产出树 **13506 → 打包 → 6492 → 解回 13501**，逐文件比下来：
**唯一真正的"少"是 35 个 `.ogg` 与我们的账本文件**（前者变成了波形条目、后者本来就不是资产），
其余差异**全部能指到一处已文档化的既定转换**（预乘 / `.png` 剥扩展名 / 缺省物化 / 大小写归一 /
框架字段）。⇒ **打包→解包这一段没有引入内容丢失**。
⚠ 仍然**没有实机验证**（见 `how-to-build-an-install.md` §5）。

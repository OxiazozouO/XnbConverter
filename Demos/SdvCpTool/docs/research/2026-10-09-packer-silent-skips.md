# 打包器会**静默跳过**没有 `.config` 边车的文件（实机验证时踩到的）

日期：2026-10-09

**怎么发现的**：做第一次实机验证时，手工把「女巫沼泽扩展」产出树里的**变更文件**
挑出来打包成 XNB 放进游戏副本。摘要显示：

```
成功: 17
失败: 0
```

看着像**全打成功了**。实际那个目录里应该有 **37** 个资产（20 个改过的原版资产 + 17 个新增的）。

**根因**：打包器（`XnbConverter.Cli pack`）靠 `.config` 边车**认类型**；
没有边车的文件**它不打包、也不报失败**。我挑文件时只挑了「与原版不同」的，

- **新增**的资产自带边车（工具写出来的）⇒ 打进 17 个 ✓
- **改过**的**原版**资产，它的 `.config` **与原版逐字节相同**、因而**不算变更**、没被我挑中
  ⇒ 打包器认不出类型 ⇒ **静默跳过 20 个**

补上同名 `.config` 后重打 → **37 个** ✓

## 对仓库里现有脚本的影响：**没有**

`tools/pack-check.py` 的注释里已经点名了这件事
（「`.config` 边车……都不在里面」指的是「不能只靠报告的 `target` 找文件」，
它**显式**把边车一起拷进小树）⇒ `roundtrip-all.py` 那份「3794 成功 / 0 失败」是**可信的**。

⇒ 这是个**手工打包**才会踩的坑。

## 另一件（**未确证**）

第一次调用时我**没有预先创建** `-o` 指向的目录，结果那个目录**根本没被创建**，
`find` 直接报「No such file or directory」。**能确定的只是**「输出目录不存在」；
**没确认**打包器当时到底把文件打去了哪里（它的 stdout 被中文编码搞花了，只看到
「处理完成 … 文件数」一类的字样）。

⚠ 所以「`-o` 目录必须先存在、否则静默不输出」这句是**推测**，
**未确证**。稳妥做法就是**先 `mkdir`**再调用（第二次这么做，成功了）。

## 教训

**打包器的「失败: 0」不等于「没漏东西」。** 拿 XNB 数量对一下**预期资产数**，
或者干脆走 `tools/pack-check.py`（它会把边车和 `.config` 一起处理）。

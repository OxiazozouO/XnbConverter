## 2. ★ 最简模型（被证伪后修正的版本）

### 2.1 被证伪的原假设

我原来的假设：`索引 = 块号 × N + 槽号`，**`N` = 变体维度的基数**。

**❌ 证伪。核心裂缝：`N` 的含义搞混了。**

> **`N` = 每行格数 = `纹理宽 / 格宽`（几何常数），不是语义维度的基数。**

- 衬衫 `N=16`，但衬衫**没有任何 16 值的语义维度**
- `springobjects` N=24、`Objects_2` N=8 —— **同一类物品，N 随图集宽度变**
- BigCraftable Seasonal 的 `N=4` 之所以等于季节数，是**作者刻意把四季排在连续 4 格**

**两个决定性反例**（形式与语义都塞不进那个式子）：

```csharp
// ① Fence.cs:179 稀疏键字典——槽空间 {0,10,100,110,500,1000,…}，非 0..N-1，且非单射
fenceDrawGuide = new Dictionary<int,int>{ [0]=5, [500]=5, … };

// ② Data/animationDescriptions 的任意帧列表——可重复、非单调
"clint_hammer" = "4/8 8 8 8 8 8 8 8 8 8 8 8 10 11 9 8/8"
```

**其余反例族**：表驱动置换（地板 16 项表、玩家 **126 项**偏移表）、非单射塌缩（**Bush 春=夏同格**）、
哈希/奇偶（杂草 `x*51+y*77 % 3`）、**跨资产**（7 张家具图集）、数据给的 N。

### 2.2 ✅ 修正后的模型：**三层**

```
显示 = (Texture, 槽 → 矩形)
       ① 选哪个 Texture
       ② 选哪个「候选槽」（谓词 + 选择序）
       ③ 槽 → 矩形（映射族）
```

| 层 | 路径 |
|---|---|
| **① 容器** | 字段（`Texture`）/ 名字拼+探测（`_Beach`、`.locale`）/ 目录约定（`Characters/Monsters/`）|
| **② 槽** | 谓词载体：GSQ 字段 / **键名** / **值内联**（`$query`、`ConditionalDoor`）/ **名字子串**（`Seasonal`）<br>选择序：首个命中 / 最低 `Precedence` / **加权随机** / 优先链 |
| **③ 槽→矩形** | **三族：算术拆包 / 表映射 / 哈希** |

**「条件」是两条式**（不是一条）：

```
选择式：值 = select(候选表, 谓词, 序)      ← 绝大多数
触发式：if (谓词) 执行(副作用)             ← Action / TriggerActions / 名字分类
```

### 2.3 「前缀 vs 后缀」有答案了，且**有断代物证**

| | 谁决定 | 例子 |
|---|---|---|
| **前缀** | **内容作者**（写在 `.tbin` 里，Tiled 中可见）| `spring_outdoorsTileSheet` |
| **后缀** | **引擎**（`base + sep + tag` + `DoesAssetExist` 探测）| `_Beach`、`_dangerous`、`.locale` |

```
Game1.objectSpriteSheetName = "Maps\\springobjects"   ← 冻结字面量
全库搜 summerobjects/fallobjects/winterobjects  →  0 命中
而 1.6 新增的第二张物件图集叫 TileSheets\Objects_2    ← 后缀式
```

**→ 前缀是 1.0 时代的遗留（那时没有数据驱动），后缀是现行做法。**
**季节本身两种方向都有**：地图 tilesheet 用前缀，**WorldMap 用后缀**。

## 6. 用户教的三条方法（已内化）

1. **源码无解时 → 去看素材的实际布局**（「四季在连续 4 格」就是线索）
2. **充分量化 → 不只要找机制，要量出每类的语料用量**
3. **游戏的语义常说在「名字」和「索引运算」里，而不在数据模型里**
4. **同功能多实现 → 找最简模型，用它统一**（本文件 §2）
